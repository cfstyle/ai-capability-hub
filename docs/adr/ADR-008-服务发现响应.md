# ADR-008：服务发现响应（server/discover）规范

**状态：** 已批准  
**日期：** 2026-11-12  
**决策者：** 项目组  

## 背景（Context）
- MCP `2026-07-28` 规范定义了服务端必须实现的 `server/discover` 方法，向客户端说明服务端的协议版本、能力特性、静态说明和缓存控制参数。
- 作为聚合网关，Hub 若机械拼接或汇总下游各服务的发现响应，会导致协议版本冲突、静态 Instructions 混乱以及拓扑结构泄漏。

## 决策（Decision）
1. **统一发布自身能力：**
   - Hub 的 `server/discover` 响应仅发布 Hub 自身的能力与元数据，严禁汇总或透传下游 Server 的发现信息。
2. **字段取值规范：**
   - `supportedVersions`：仅列出 Hub 自身实际对外支持的新版协议版本（如 `["2026-07-28"]`），不合并下游支持的版本。
   - `capabilities`：首版仅声明 `tools` 能力；暂不声明 `resources`、`prompts`；暂不声明 `tools.listChanged` 主动通知能力。
   - `serverInfo`：返回 Hub 自身服务标识与版本，统一封装在协议规定的 `_meta` 结构中。
   - `instructions`：返回 Hub 自身维护的全局静态使用说明与调用须知，不拼接下游零散的说明文本。
   - `ttlMs`：统一配置为 `0`。
   - `cacheScope`：统一配置为 `private`。
   - `resultType`：统一配置为 `complete`。
3. **变更通知策略：**
   - MVP 阶段不实现基于 `subscriptions/listen` 的工具动态变更主动广播（`notifications/tools/list_changed`）。工具清单变更通过客户端按需重新查询或管理员手动刷新完成。

## 影响（Consequences）
- **正面影响：**
  - 对外提供统一、规范的服务端契约，屏蔽了内部复杂异构的多服务实现细节。
  - `ttlMs=0` 和 `cacheScope=private` 确保了权限变更或工具上下线后，客户端能即时感知最新的工具状态，防止安全越权。
- **负面影响：**
  - 客户端无法依赖长连接主动推送感知工具变更，需在重新建连或重新请求时同步最新目录。
