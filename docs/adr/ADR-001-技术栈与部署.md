# ADR-001：Hub Core 技术栈与离线部署

**状态：** 已批准  
**日期：** 2026-11-12  
**决策者：** 项目组  

## 背景（Context）
- 银行内网环境要求具备严格的安全隔离和可维护性。
- 需要选择团队熟悉、生态成熟且与 MCP 协议演进紧密结合的语言与框架。
- 部署环境为隔离内网，无外网访问权限，无法在部署时动态拉取镜像或执行 `pip install`。
- Hub Core 负责标准化接入和统一治理，需要明确技术选型与容器化交付策略。

## 决策（Decision）
1. **Hub Core 开发语言：** 采用 Python 3.11+。
2. **核心技术组合：**
   - **MCP 协议与聚合：** FastMCP（用于 MCP 聚合代理验证）及官方 `mcp` SDK 2.x
   - **管理 REST API：** FastAPI
   - **HTTP/ASGI 服务器：** Uvicorn
   - **下游网络访问：** HTTPX（优先使用 SDK 提供的 MCP Client 传输层）
   - **数据校验与配置：** Pydantic、PyYAML
   - **元数据持久化：** SQLite（MVP 单实例），后续根据并发需求演进为 PostgreSQL
3. **部署架构：** 采用 Docker Compose 离线镜像交付。
   - 在可访问依赖仓库的受控联网构建环境中构建镜像，锁定依赖版本并生成软件物料清单（SBOM）及镜像摘要。
   - 导出为完整离线镜像包，经内网安全扫描后导入目标内网宿主机。
   - 使用 Docker Compose 启动全套服务（Hub Core 及各业务 Mock MCP Server）。
   - SQLite 数据库、注册配置文件和调用日志挂载持久化 Volume。
   - 内部服务通过 Docker 内部网络互联，仅 Hub Core 对客户端暴露访问端口，下游 MCP Server 默认不直接暴露。
   - 生产环境禁止现场动态拉取镜像或临时下载编译软件包。
4. **业务服务多语言解耦：** Hub 采用 Python 并不限制业务团队开发 MCP Server 的语言，支持 Java、Python、Go、Node.js 等跨语言独立开发与容器化部署。

## 影响（Consequences）
- **正面影响：**
  - 技术选型轻量、开发与调试效率高，贴合团队已有技术栈。
  - Docker Compose 离线交付完全符合银行隔离内网的安全合规与交付规范。
  - 核心平台与业务能力彻底解耦，不绑定业务团队的技术选型。
- **负面影响：**
  - SQLite 在高并发写入场景下存在锁限制，需控制写入并发；后续多实例扩展时需平滑迁移至独立关系型数据库。
  - 离线镜像交付需要建立标准化的前置构建、扫描与导出流程。
