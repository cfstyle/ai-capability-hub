# ADR-006：MCP 协议版本基线与多版本兼容策略

**状态：** 已批准  
**日期：** 2026-11-12  
**决策者：** 项目组  

## 背景（Context）
- MCP 规范演进迅速，不同时期发布的规范在协议握手、Session 机制、健康探测及发现接口上有明显差异。
- 目标测试客户端（DeepSeek Harness）及下游业务系统的实际协议支持情况存在不确定性。
- 官方 SDK 支持多版本不等于 Hub 的聚合层能无损透传所有协议扩展能力。必须划定明确的版本支持基线。

## 决策（Decision）
1. **协议支持矩阵：**
   - `2026-07-28`：**首选基线**，Hub 对外统一暴露该规范的 Streamable HTTP 接口，采用无状态请求模型。
   - `2025-11-25`：**条件兼容**，通过独立端到端测试验证后支持，重点适配其握手与会话机制。
   - `2025-06-18`：作为后续兼容候选版本，视接入系统需求评估。
   - `2025-03-26` 及更早版本：暂不承诺支持。
   - `2024-11-05` (HTTP+SSE)：首版明确**不支持**。
2. **兼容性验证与功能范围：**
   - 在 P0 阶段建立端到端实测矩阵（DeepSeek Harness ↔ Hub Core ↔ 下游 Mock Server）。
   - 首版仅承诺通过实测的 `tools/list` 和 `tools/call` 基础功能，不承诺兼容所有实验性或高级 MCP 扩展。
   - 对下游依赖的无法无损代理的能力（如服务端主动采样、反向请求、复杂交互确认），显式标记为“暂不支持”，杜绝静默失败。

## 影响（Consequences）
- **正面影响：**
  - 聚焦最新标准，避免在网关内部引入沉重的历史协议兼容包袱。
  - 明确了各协议版本的准入与支持范围，降低了开发和排错成本。
- **负面影响：**
  - 无法直接接入早期仅支持 HTTP+SSE 的旧版 MCP 服务，需要下游服务升级或引入独立适配器。
