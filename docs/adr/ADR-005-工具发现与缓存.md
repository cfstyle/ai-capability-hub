# ADR-005：工具发现策略、变更审核与权限缓存

**状态：** 已批准  
**日期：** 2026-11-12  
**决策者：** 项目组  

## 背景（Context）
- 下游业务 MCP Server 可能会升级接口、修改参数 Schema 或增删能力。
- Agent 客户端通常在任务规划阶段调用 `tools/list` 缓存工具目录，工具频繁变动或缓存混乱易引发大模型调用失败或幻觉。
- 银行内不同岗位的员工可见能力不同，若全量缓存或全局共享缓存会导致低权限用户非法感知未授权工具（越权发现）。

## 决策（Decision）
1. **工具发现的三重触发机制：**
   - **注册时发现：** 服务注册时，Hub 主动连接下游服务，获取完整工具清单与参数 Schema，生成基线快照。
   - **启动时校验：** Hub 启动时，自动校验所有已激活服务的连通性与工具快照版本一致性。
   - **管理员主动刷新：** 工具变更需由管理员在管理 API 显式触发重新发现与比对。契约发生不兼容变更时，未经人工审核不自动覆盖已发布的工具契约。
2. **工具命名空间规范：**
   - 统一采用 `{service_id}__{tool_name}`（例如 `ticm__portfolio_summary`）格式，确保全局唯一且可逆。注册时发现名称冲突直接拒绝。
3. **按权限隔离的工具发现与缓存：**
   - 响应 `tools/list` 时，Hub 动态基于当前用户 JWT 中的权限声明进行过滤，仅返回被授权的工具列表。
   - 严禁全局缓存全量工具清单供所有用户共享。
   - 遵循 MCP 协议缓存控制规范：对外设置 `ttlMs = 0`，`cacheScope = private`，防止客户端或反向代理缓存过期或越权目录。
4. **服务健康与目录管理：**
   - 下游服务发生偶发故障或探测不可用时，不立即从工具目录剔除，避免打乱 Agent 的规划上下文；调用时返回明确的不可用错误。
   - 仅在管理员正式下线服务或发生高危安全风险时，才从目录中移除工具暴露。

## 影响（Consequences）
- **正面影响：**
  - 严格保障了工具可见性的权限隔离，杜绝越权探测。
  - 建立了工具契约变更的审计防护，防止下游未经通知的修改破坏正在运行的 Agent 任务。
  - 避免服务偶发抖动导致 Agent 工具缓存频繁雪崩。
- **负面影响：**
  - `ttlMs=0` 导致客户端每次查询工具均需请求 Hub，增加了工具列表序列化开销（MVP 规模工具数量较少，性能影响可忽略）。
